# Independent asset-control observations

This module is separate from the digital-file marketplace; no ownership transfer, NFT custody, bridge or token-balance verification is performed. Claims show technical control at observation time, not legal title or perpetual ownership. Results are private to the requesting account and expire after 24 hours.

Every ten-minute challenge includes `asset-control/v1`, exact platform origin, account UUID, canonical subject/kind, challenge UUID, a random 256-bit nonce and expiry. Challenges are account-bound, single-use and limited to five observation attempts. Verification rechecks expiry/consumption after network work in a transaction. EIP-191 signatures cannot be replayed for another domain, account, subject, chain label or challenge.

- **DNS:** publish the returned hash marker as the exact `_arcana-control.<ASCII-domain>` TXT value. Segmented TXT strings are joined. The server performs TXT resolution only, never HTTP requests to the resolved address. Invalid/IP/local/internal names are rejected; control can be delegated through DNS and DNS security still depends on the resolver/zone. No DNSSEC trust guarantee is made.
- **GitHub:** place the exact marker in `.well-known/arcana-control.txt` on the public repository's `main` branch. The only HTTP target is a constructed, validated `raw.githubusercontent.com` path; redirects are forbidden, deadline five seconds and response cap 4 KiB. Proxy/CA environment settings are preserved through Undici's environment proxy agent. Private repositories, OAuth organization roles and alternate branches are not supported by this first verifier.
- **EVM:** sign the complete human-readable statement using EIP-191 personal_sign. `ethers@6.17.0` performs standard recovery/address checks. Chain labels 1, 137, 42161 and 8453 are supported; no chain RPC is queried, so this proves signing-key control, not asset balances, contract-wallet EIP-1271 authorization or a blockchain transaction.

DNS failures, missing markers, HTTP policy denials and invalid signatures never create successful verifications. Automated DNS/GitHub success tests inject synthetic observation transports; EVM tests generate a real local key/signature but do not send a chain transaction. No live domain/repository-control observation is claimed without an actual published challenge. The user-controlled transport is not exposed in any HTTP input.
